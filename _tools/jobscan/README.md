# jobscan — สแกนงานจาก Fastwork job board

สแกน `jobboard.fastwork.co` ทุก 2 ชม. ในเวลาทำการ จัดอันดับตามความเข้ากับงานที่ส่งมอบได้จริง
แล้วแจ้งเฉพาะ **งานใหม่** เข้า GitHub Issue (+ Discord ถ้าตั้ง webhook)

รันบน GitHub Actions ไม่ใช่บนเครื่อง — `.github/workflows/jobscan.yml`

## ใช้ยังไง

```bash
# ลองเกณฑ์คะแนนกับข้อมูลจริงที่เก็บไว้ — ไม่ต่อเน็ต ไม่เขียน state ไม่แจ้งเตือน
python3 _tools/jobscan/scan.py --dry-run --fixture _tools/jobscan/fixtures/jobs.json

# รอบแรกของจริง: จำ id ไว้เฉย ๆ ไม่แจ้งเตือน
python3 _tools/jobscan/scan.py --state-dir _state --seed

# รอบปกติ
python3 _tools/jobscan/scan.py --state-dir _state
```

## แหล่งข้อมูล (วัดเมื่อ 2026-08-24 ไม่ได้เดา)

หน้า `jobboard.fastwork.co/jobs` เป็น Next.js shell — `__NEXT_DATA__` มีแต่ i18n — รายการงาน
มาจากอีก host หนึ่งซึ่ง **ตอบ HTTP client เปล่า ๆ ได้ ไม่ต้อง auth ไม่ต้อง cookie ไม่ต้องเบราว์เซอร์**

| | |
|---|---|
| งาน | `GET https://jobboard-api.fastwork.co/api/jobs` → `{data: [...], meta: {...}}` |
| หมวด | `GET https://jobboard-api.fastwork.co/api/tags` → 24 หมวด |
| กรองหมวด | `filters[0][field]=tag_id&filters[0][value]=<uuid>` — **สะกดแบบนี้แบบเดียว** ที่ใช้ได้ (`tag`, `tag_ids`, `tag.id`, `tag_name` ตอบ HTTP 400) |
| ลิงก์งาน | `https://jobboard.fastwork.co/jobs?job_id=<uuid>` — แบบ `/jobs/<uuid>` คือ 404 |
| robots.txt | `Allow: /` ห้ามแค่ `/me/` กับ `/en/` |

**บอร์ดนี้เป็นบอร์ดงานทั่วไป** — เปิดอยู่ ~3,000 รายการ ส่วนใหญ่เป็นไลฟ์สไตล์ ช่าง งานสอน
"เพื่อนชวนคุยแก้เหงา" หมวดพัฒนาเว็บไซต์มีแค่ ~41 รายการ **การเลือกหมวดจึงจำเป็น ไม่ใช่การกรอง
งานทิ้ง** และเป็นเหตุผลที่สแกนหนึ่งรอบใช้แค่ไม่กี่ request แทนที่จะไล่ 600 หน้า

⚠️ **API เคยตอบ HTTP 500 กับ query ที่ไม่กรอง** ทั้งที่ request เดียวกันตอบ 200 เมื่อ 3 นาทีก่อน
`_get()` จึง retry 5xx แบบ backoff และไม่ retry 4xx เลย (request ที่ผิดอยู่แล้ว ยิงซ้ำก็แค่รบกวน
เขาเปล่า ๆ)

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `recon.py` | สำรวจว่าบอร์ดเสิร์ฟข้อมูลยังไง — รันตอนเริ่ม หรือตอนที่ parser พัง |
| `fetch.py` | ดึงจาก API + retry + แปลงชื่อหมวดเป็น `tag_id` ตอนรัน |
| `normalize.py` | แปลง record ดิบ 31 ฟิลด์เป็นรูปแบบแบน |
| `score.py` | ให้คะแนน + เหตุผล อ่านเกณฑ์จาก `profile.json` |
| `profile.json` | **เกณฑ์ทั้งหมดอยู่ที่นี่** หมวด คำ น้ำหนัก — แก้ได้โดยไม่ต้องแตะโค้ด |
| `state.py` | `seen.json` (กันแจ้งซ้ำ) + `jobs/YYYY-MM.jsonl` (เก็บย้อนหลัง) |
| `notify.py` | GitHub Issue + Discord |
| `scan.py` | ร้อยทั้งหมดเข้าด้วยกัน |

## สี่อย่างที่ตั้งใจให้เป็นแบบนี้

**คะแนนใช้จัดอันดับ ไม่ได้ใช้กรอง** งานทุกรายการในหมวดที่เลือกขึ้น digest หมด คะแนนบอกว่าควรอ่าน
อันไหนก่อน `reasons` บอกว่าทำไม — ตัวกรองที่ตัดงานผิดตัวทิ้งจะไม่มีใครเห็น ส่วนงานอันดับท้าย ๆ
ที่มีเหตุผลกำกับ ยังอยู่ให้เถียงได้

**ดึงได้ 0 รายการ = error ไม่ใช่ "ไม่มีงานใหม่"** parser ที่พังกับบอร์ดที่ว่างจริงให้ผลหน้าตา
เหมือนกันเป๊ะ อย่างหลังต้องดังกว่า ใส่ `--allow-empty` ถ้าตั้งใจ

**รอบแรก seed เงียบ ๆ** `seen.json` ที่ว่างเปล่าจะมองว่าทั้งบอร์ดคืองานใหม่ ถ้าแจ้งเลยจะได้ issue
เดียวยาว 149 บรรทัด

**ชื่อหมวดถูกแปลงเป็น `tag_id` ตอนรัน ไม่ hardcode uuid** ถ้าหมวดถูกเปลี่ยนชื่อ การกรองจะเงียบ ๆ
เหลือศูนย์แทนที่จะฟ้อง — ตอนนี้ชื่อที่แปลงไม่ได้จะถูกพิมพ์ออกมาพร้อมรายชื่อจริง และถ้าแปลงไม่ได้
สักหมวด มันจะไม่ยอมสแกนทั้งบอร์ดแทน

## fixture

`fixtures/jobs.json` คือ payload จริงจากบอร์ด เก็บโดย workflow ไม่ได้เขียนมือ — เกณฑ์คะแนนจะได้
จูนกับงานจริง ไม่ใช่กับตัวอย่างที่แต่งขึ้น

⚠️ ตอนโหลด `scan.py` จะ **normalize ใหม่จาก `raw` ที่เก็บไว้** ไม่เชื่อฟิลด์ที่ normalize ไว้แล้ว
ในไฟล์ — ไม่งั้น fixture ที่เก็บก่อนแก้ `normalize.py` จะยังเทสต์พฤติกรรมเก่าอยู่ (บั๊ก `฿0` จะดู
เหมือนแก้แล้วทั้งที่ fixture ยังบอก ฿0)

## state เก็บที่ไหน

branch `jobscan-state` (orphan) ไม่ใช่ `main` — `main` auto-deploy ไป GitHub Pages ทุก commit
การเขียน state ลง `main` = deploy วันละ 7 ครั้งโดยที่เว็บไม่มีอะไรเปลี่ยน

## มารยาทกับปลายทาง

`recon.py` อ่าน `robots.txt` แล้วเช็คด้วย `urllib.robotparser` ก่อน ถ้า `/jobs` ถูก `Disallow`
มันจะ **หยุดและรายงาน** ไม่ใช่หาทางอ้อม User-Agent บอกตรง ๆ ว่าเป็นอะไรและติดต่อใครได้ ยิงไม่กี่
request ต่อรอบ เว้นจังหวะระหว่าง request วันละ 7 รอบ และไม่เอาข้อมูลไปเผยแพร่ต่อ
